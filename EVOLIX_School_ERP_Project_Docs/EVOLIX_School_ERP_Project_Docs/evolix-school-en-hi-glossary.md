## Translation Rules
1. Never use English display text as the translation key.
2. Use stable keys such as `students.actions.add`, `finance.receipts.cancel`, `attendance.status.absent`.
3. Do not translate IDs, codes, UUIDs, or internal enum values.
4. Do not auto-translate user-entered names.
5. Keep widely understood technical terms where forced Hindi would reduce usability.
6. Use the same Hindi term consistently across the ERP.
7. Print templates may choose English, Hindi, or bilingual layouts.
8. Add new module terminology to this glossary before release.
